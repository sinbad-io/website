---
title: Superintelligence is a storage problem
date: 2026-10-23
summary: Why I think agents should keep what they know apart from the model
plate: swell-cyan-3
---

Models get better every few months, and people don't. Still, most AI today is built around a person. You paste in the context, read the answer and carry what matters over to the next chat. The model does the computing and you do the remembering, so the whole thing improves only as fast as you do.

I think this changes when the model becomes a stateless function you swap whenever a better one ships, and everything the agent knows lives somewhere that outlasts it. Its files, its memory, its unfinished work and the log of every call it made.

Infrastructure has gone through this a few times already. Kubernetes moved state out of servers into etcd, so a pod can die and the next one starts from the same desired state. Neon took the disk out of Postgres, so compute holds nothing, a branch is copy on write and an idle database costs only its bytes. turbopuffer did the same for search, with S3 as the source of truth and NVMe as a cache. When Databricks bought Neon in 2025, more than 80 percent of the databases on it were being created by agents, which says a lot about who this design ends up serving.

The version I keep coming back to puts the whole agent on a bucket. One LSM tree on S3, with its WAL, its SSTs and a manifest. Since 2024 S3 can compare and swap on a write, which is enough to fence off a stale writer without a consensus service beside it. Each step of the agent commits as one write, so the email and the memory of sending it land together or not at all.

Latency looks like the weak point, but a write to S3 takes tens of milliseconds and a step already waits seconds on a model, so it barely shows. Cost matters more. A gigabyte in S3 is about 2 cents a month, against about 24 on replicated SSD and around 5 dollars in RAM. Keeping everything an agent has ever done is only affordable at the first price, and an agent that is asleep costs nothing beyond its bytes.

What I find most interesting is how much follows from files that never change. A fork is a new manifest pointing at the same files, so an agent can be copied in under a second and try a problem ten ways at once. A new model can replay last month's work before it touches anything real, and each correction a person makes becomes a test the next model has to pass.

If that holds, a new model no longer starts over. It picks up where the last one stopped, and the agent gets better with every release without a person having to carry it. That is most of what I mean when I say superintelligence is a storage problem.
